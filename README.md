# Switch 2 の言語設定を変更する

Switch 2 の `set` / `set:sys` を使って、本体の言語設定を書き換える実験コード。`pepsipu/ns2jb` をベースに、17言語の選択と日本語への復元を追加した。

試した環境は **FW 23.0.1 / SmileBASIC 4.4.9**。

## 実行

Node.js 22以降が必要。言語をダイアログから選ぶ場合は Zenity も必要。

```sh
node set-language.cjs --boot-id boot-20261112-01                  # 言語を選ぶ
node set-language.cjs --language ko --boot-id boot-20261112-01    # 韓国語に変更
node enable-english.cjs --boot-id boot-20261112-01                # 英語に変更
node restore-japanese.cjs --boot-id boot-20261112-01              # 日本語に戻す
```

PCのLAN側IPv4アドレスは自動で選ぶ。候補が複数ある場合はターミナルで番号を選ぶ。手動指定するならコマンド末尾にIPv4アドレスを付ける。

上の4行は別々の実行例。同じ完全OS起動では**どれか1回だけ**使い、起動ごとに `--boot-id` を新しい値（英数字・`_`・`-` の16〜64文字）にする。使用済みIDは記録され、同じIDでの再実行は止まる。JSONファイルは不要。起動の新しさやSAVE内の残留物は自動判定しないので、START未使用と作業ファイルの有無を実行前に確認する。言語選択のキャンセルや不正な指定は、待受開始・起動ID消費前に止まる。

`0` は復元用。`18` と `19` はそれぞれ `ja` / `en-US` の重複なので選択肢から外した。

旧互換表とは番号が違う（旧表の `7` は `ko`）。実行時に `MakeLanguageCode` を照合し、対応が異なる場合は `0`〜`17` を読み直す。一意に特定できない言語には書き込まない。詳しくは [LANGUAGES.md](LANGUAGES.md)。

## どこまで動いたか

過去の実機試行では、次の結果を得ている。

- `MakeLanguageCode(0..19)` の20件すべてが、参照した設定NSOの変換表と一致（言語コード・8バイト応答）。
- 地域 `1` / `en-US` を読戻し、本体設定画面が英語になった。
- 別の実機試行では、同じ起動中に `en-US` の読戻しと『カービィ エアライダー』の英語タイトルを確認した。
- 日本語の設定値への復元も確認。
- 再起動後の別の試行では地域 `1` / `ja` が返った。

**この統合版を最初から最後まで動かした記録はまだない。** 設定変更の判定は書込み直後の読戻しで行う。再起動後に日本語へ戻った観測もある。実行ごとの記録は [EVIDENCE.md](EVIDENCE.md)。

書き換えるのは本体の可変設定値だけ。ハードウェアの地域区分やアカウントの国設定、ゲームの翻訳データは変わらない。

## 注意

**STARTは本体の完全OS起動1回につき1回。** 応答がなくても再送しない。

### 失敗して応答がなくなったら

1. **STARTを再送しない。** 言語変更や日本語復元のコマンドも続けて実行しない。
2. PC側の `runs/` ディレクトリを丸ごと手元に保管する。`runs/switch2-*/result.json` と `switch2/memory/` のraw記録を消さない。`connect.txt` や `connection.json` には接続情報があるので、フォルダを公開Issueに添付しない。
3. SAVE内に本コードの作業ファイルが残った場合、**この配布物だけで実行できる回収コマンドはまだない。** `recovery/` はrawから所有ファイルを特定し、内容照合・非再帰削除を行うための内部ライブラリで、Switch 2への接続・別起動の確認・削除後の再読込みまで行うCLIではない。`node recovery/*.cjs` や手作業の一括削除をしない。rawと実行元ソースを保全したまま、個別の回収手順を準備するまで次のSTARTを控える。

回収を実行する段階では、**別の完全OS起動**、その実行のrawとソースに一致する対象だけの照合、非再帰削除とcommit、再マウント後の不在確認が必要。いまのZIPは利用者が自分で回収まで完結できる配布物ではない。

90DNS／オフライン設定を維持する。Nintendoのオンライン接続や本体更新、PRODINFO・シリアル・鍵・DNSの変更は行わない。ログや接続トークンは公開Issueに貼らないこと。

## テスト

`bootstrap.bas` は上記FW・SmileBASICで使った起動ソース。SDK相対オフセットとハッシュを検査するので、別ビルドにオフセットだけ流用しないこと。`engine/` にFSメモリ・設定操作、`recovery/` に回収処理がある。

```sh
node run.cjs --check-only  # 本体に接続せずにチェック（ダイアログ・START送信なし）
node --test boot-journal.test.cjs host-network.test.cjs language-dialog.test.cjs recovery/recovery.test.cjs $(find engine -name '*.test.cjs' | sort)
```
